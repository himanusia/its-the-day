# Incremental delivery contract

User requested smaller verifiable iterations instead of one all-or-nothing completion.

## Iteration 1: usable local tracker
- Restore a clean Flutter analyze and passing tests.
- Deliver local quantity goal: target 50 shorts, deadline 2027-01-01, add/edit/remove results with optional explanation.
- Preserve countdown, checklist and persistence.
- Keep incomplete online features explicitly unavailable rather than wiring missing screens.
- Build an Android APK from this exact revision and exercise the local flow.
- Stop at this checkpoint and report artifact, checks and remaining limitations. No online integration or cosmetic expansion in this iteration.

## Subsequent independent checkpoints
2. Account sign-up/sign-in/sign-out, verified against the local server.
3. Create/join groups and add shared quantity progress, verified using two accounts.
4. Individual targets, member management and remaining group flows.
5. Widget runtime verification and visual/animation polish.

## Reporting
Report implemented, tested and delivered separately. No weighted completion percentage as proof. End each bounded work unit with real check output; failed checks become the next immediate task, not a reason for open-ended research. No production deployment without authorization.
